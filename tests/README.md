# Тесты платформы

Заменяют `curl_tests_f1.md` / `curl_tests_f2.md`: тот же сценарный охват, но
выполняемый и проверяющий результат, а не печатающий его в терминал.

## Запуск

```bash
# всё, без внешнего окружения — ни Postgres, ни Ollama, ни Qdrant, ни MinerU
python -m unittest discover -s tests -t .

# по одному агенту
python -m unittest tests.test_agent_epoz
python -m unittest tests.test_agent_document_chat
python -m unittest tests.test_agent_slave_chat

# подробно, с именами и причинами пропусков
python -m unittest discover -s tests -t . -v
```

Против реально поднятого стека — задайте `MASTER_URL`, тесты те же:

```bash
   -m unittest discover -s tests -t .
```

Переменные окружения:

| | |
|---|---|
| `MASTER_URL` | адрес мастера; задан — режим LIVE, не задан — STUB |
| `TEST_USER_ID` | пользователь, от имени которого идут запросы |
| `TEST_TIMEOUT` | таймаут HTTP-клиента, секунды. По умолчанию — `agent_timeout` мастера плюс 30: тест не должен сдаваться раньше самого мастера, иначе вместо осмысленного ответа приходит `httpx.ReadTimeout` |
| `TEST_MAX_TOKENS` | ограничение длины ответа, подставляемое в каждый запрос генерации |

`TEST_MAX_TOKENS` заметно ускоряет LIVE-прогон и ничего не искажает:
проверяется форма ответа, а не его содержание. Разумное значение — 64–128.

```bash
MASTER_URL=http://127.0.0.1:8000 TEST_MAX_TOKENS=64 \
  python -m unittest tests.test_agent_tech_rag
```

LIVE-прогон медленный по своей природе: каждый тест реально дёргает модель, а
на один агент их около тридцати. С большой моделью полный набор идёт десятки
минут — это ожидаемо, а не признак поломки.

Пакет `openai` не обязателен, но с ним проверки строже: формы ответов
валидируются против pydantic-моделей SDK. Без него эти проверки не
пропускаются молча — они просто сверяют структуру мягче.

## Два режима

| | STUB (по умолчанию) | LIVE (`MASTER_URL`) |
|---|---|---|
| мастер | поднимается в процессе | по HTTP |
| агенты | эталонная реализация контракта in-memory | настоящие |
| роутинг | детерминированная заглушка | реальные эмбеддинги + LLM |
| что проверяется | всё, за что отвечает мастер | плюс семантика и содержательность |
| нужно внешнее | ничего | весь стек |

В STUB-режиме подменяются ровно две вещи: тяжёлые зависимости роутинга
(`sentence_transformers`, `ollama` грузят модели прямо на импорте) и транспорт
до агентов. **Класс адаптера при этом настоящий** — проброс статуса,
content-type и потокового тела проверяется на реальном коде мастера, а не на
моке.

Тесты, которым нужен живой стек, помечены `@env.live_only` и в STUB-режиме
пропускаются с внятной причиной, а не выдают ложно-зелёный результат.

## Структура

```
tests/
├── support/
│   ├── env.py          режим запуска, константы, декораторы пропуска
│   ├── stubs.py        подмены зависимостей и транспорта
│   ├── fake_agent.py   эталонная реализация контракта агента
│   ├── client.py       единая точка входа: live HTTP или приложение в процессе
│   └── base.py         MasterTestCase + AgentContractTests
├── test_master.py               мастер: модели, роутинг, формы, auth, ошибки, проброс
├── test_routing.py              MasterRouter отдельно, без HTTP
├── test_agent_epoz.py           RAG по закупкам
├── test_agent_tech_rag.py       RAG по техдокументации
├── test_agent_slave_chat.py     общий чат (id "chat")
├── test_agent_document_chat.py  документы + /v1/files
└── test_agent_ocr.py            OCR — вне OpenAI-контракта, намеренно
```

### Почему общий контракт вынесен в миксин

В curl-файлах один и тот же набор проверок был скопирован по разу на агента —
и копии успевали разойтись: у одного проверялся `/sources`, у другого нет; в
одном месте ожидался `422`, в другом `400`. Теперь контракт описан один раз в
`AgentContractTests`, а различия агентов выражены атрибутами класса:

```python
class EpozContractTests(AgentContractTests, MasterTestCase):
    AGENT_ID = "epoz"
    HAS_SOURCES = True
    QUESTION = "что такое закупка"
```

Новый агент подключается тремя строками и сразу получает ~30 проверок.
Разойтись копиям больше негде.

`HAS_SOURCES` работает в обе стороны: у RAG-агента проверяется, что `/sources`
отвечает, у остальных — что его нет. Различие между агентами должно быть
заявленным, а не случайным.

### `fake_agent.py` — исполняемая спецификация

Это не «мок, возвращающий заглушку», а минимальная, но честная реализация
контракта: обе формы, стрим, фидбэк, чаты, файлы, скоупинг по `X-User-Id`,
конверт ошибок. Если агент платформы расходится с ней в форме ответа —
расходится агент, а не тесты.

## Что покрыто

**Мастер** — список и получение моделей (включая обязательный `owned_by`),
выбор агента в обеих формах, отсутствие протечки `model: "auto"` наружу,
согласованность форм на одном тексте, проверка `contract_forms`, `/route`,
аутентификация (`X-User-Id` и `Authorization: Bearer`), формат ошибок,
сквозной проброс всех методов и статусов, потоковый content-type.

**Каждый диалоговый агент** — обе формы в стриме и без, единый `id` в чанках,
терминатор `[DONE]` у Chat Completions и его отсутствие у Responses,
монотонность `sequence_number`, `stream_options.include_usage`, отказ на `n>1`,
`system`/`developer`, массив частей в `content`, чтение и удаление по id,
`store: false`, `conversation` и алиас `conversation_id`,
`previous_response_id`, фидбэк, CRUD чатов, изоляция пользователей.

**document_chat** — дополнительно `/v1/files` целиком, статусы файла в
значениях OpenAI, вопрос по документу в обеих формах, отказ на инлайновое
вложение с подсказкой, маршрутизация запроса с вложением.

**ocr** — capability-ручка, отсутствие `/ocr` у остальных агентов, отказ обеих
форм и отсутствие в списке моделей.

## Проверка самих тестов

Набор проверялся мутациями: в код мастера по одному вносились дефекты
(роутер не вызывается в Responses, `owned_by` пропал, `image_url` перестал
считаться вложением, валидация вернулась к `422`, `param` не заполняется,
`Authorization` не принимается, `model` не подменяется, fallback выходит за
пределы кандидатов, ответ LLM не проверяется) — каждая мутация роняет тесты.

Если добавляете проверку, стоит убедиться тем же способом, что она способна
упасть: тест, который не падает ни на одной мутации, не проверяет ничего.
